How it works

  1. A small client runs hourly on each machine and counts its tokens with ccusage.
  2. It sends the counts to one dashboard. No prompts, no code.
  3. The dashboard splits the provider's percentage by those counts.

A menu bar app, useful with one Mac

One machine is enough. A native Mac app keeps your usage in the menu bar.

  • The week's percentage in the menu bar, with the 5-hour window as a ring.
  • Pace, what is left and the reset, one click away.
  • It reads the provider's own figure and reports for the Mac. No cron job.
  • Native and under 1 MB. You build it with one script.

Questions

Does it read my prompts or code?
No. A report holds token counts, model names, the machine's name and a cost estimate.
Does it need my provider account?
No. ccusage reads the logs the coding agents already write on your machine.
